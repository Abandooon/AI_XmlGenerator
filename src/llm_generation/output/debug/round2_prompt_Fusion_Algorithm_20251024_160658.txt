            ## AUTOSAR 组件封装原则（严格遵守）

            **关键规则：组件内部行为只能引用本组件自己的运行时元素**

            1. **事件启动约束**：
               - 所有 EVENT 的 START-ON-EVENT-REF 必须且只能引用【本组件 Fusion_Algorithm】的 RUNNABLE-ENTITY

               **路径构造规则**：
               - 格式：/Components/Fusion_Algorithm/{Runnable名称}
               - 示例（正确）：
                 * /Components/Fusion_Algorithm/Init_Runnable
                 * /Components/Fusion_Algorithm/Control_Process_Runnable
                 * /Components/Fusion_Algorithm/Periodic_Task_100ms
               - 示例（错误）：
                 * ❌ /Components/OtherComponent/SomeRunnable  （引用了其他组件）
                 * ❌ /Components/Fusion_Algorithm/Internal/SubRunnable  （路径层级错误）

            2. **端口访问约束**：
               - DATA-SEND-POINTS / DATA-RECEIVE-POINT-BY-ARGUMENTS / DATA-READ-ACCESSS 中的 PORT-PROTOTYPE-REF 必须指向【本组件 Fusion_Algorithm】的端口

               **路径构造规则**：
               - 格式：/Components/Fusion_Algorithm/{端口名称}
               - 示例（正确）：
                 * /Components/Fusion_Algorithm/P_Port_Status
                 * /Components/Fusion_Algorithm/R_Port_TempSensor
                 * /Components/Fusion_Algorithm/PR_Port_ServiceInterface
               - 示例（错误）：
                 * ❌ /Components/OtherComponent/SomePort  （引用了其他组件的端口）
                 * ❌ /Components/Fusion_Algorithm/Ports/P_Port_Status  （多了Ports容器层级）

            3. **服务调用约束**：
               - SERVER-CALL-POINTS 中的 CONTEXT-R-PORT-REF / CONTEXT-P-PORT-REF 必须是【本组件 Fusion_Algorithm】的端口
               - 路径格式同上（端口访问）

            4. **数据元素引用**（可跨组件）：
               - TARGET-DATA-PROTOTYPE-REF 可以引用任何接口中的数据元素
               - 这些路径在Schema的enum中已经为您列出，请直接选择使用

               **路径格式**：
               - 格式：/Interfaces/{接口名}/{数据元素名}
               - 示例：
                 * /Interfaces/TempSR_Interface/SeatLeft_Sensor1_Temp
                 * /Interfaces/CAN_Setting_Interface/Requested_Level_Left

            - 对于本组件的端口和Runnable引用，Schema中**没有提供enum列表**（因为生成时尚未创建）
            - 您需要根据Round1设计中的端口和Runnable名称，**手动构造正确的路径**
            - 路径必须严格遵循格式：/Components/Fusion_Algorithm/{元素名}，不要添加额外的层级

            **为什么有这些限制？**
            组件间的通信和触发必须通过端口连接间接实现，而不是直接引用。这是AUTOSAR确保组件可复用性和独立性的核心机制。
            跨组件的数据流由RTE根据端口连接（AssemblyConnector）在系统组合层面建立，而不是在组件定义层面硬编码。

            **如何正确实现跨组件通信？**
            - 组件A要触发组件B的行为：A通过自己的P-Port发送数据 → RTE传递 → B的DataReceivedEvent触发B的Runnable
            - 组件A要访问组件B的数据：A通过自己的R-Port读取 → RTE从B的P-Port获取数据
            - 组件A要调用组件B的服务：A通过自己的R-Port调用 → RTE路由到B的P-Port实现的服务

            所有 *REF 字段为对象，包含 @DEST 与 #text 两个字段：
            - @DEST：引用目标的类型（从Schema的enum中选择）

            **路径填写策略**：
            1. 如果Schema的#text字段有enum列表 → 从enum中选择一个路径
            2. 如果Schema的#text字段没有enum（通常是本组件引用）→ 手动构造路径

               - 元素名从Round1设计的element_design中获取

            仅使用 Schema 中出现的字段；不要新增未定义字段。

## 引用路径规范
所有 *-REF 必须使用完整的绝对路径，不允许语义化描述。
- 组件路径示例：/Components/<ComponentShortName>
- 端口路径示例：/Components/<ComponentShortName>/Ports/<PortName>
- 接口路径示例：/Interfaces/<InterfaceShortName>
