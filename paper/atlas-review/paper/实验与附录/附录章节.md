# 附录

本附录补充案例来源、比较条件、验证器覆盖、统计方法与失败分析。各实验保留自己的观察单位和分母，不合并不同任务的成功率。完整案例、生成配置、原始输出、检查记录及分析程序见随文复现包；依赖安装、传输处理和逐条复核操作由包内说明提供。

## 附录 A AUTOSAR 案例与受控修复

### A.1 案例来源及任务范围

本实验采用 AUTOSAR Classic 4.2.2 的组件建模子集 [12]。Software Component Template 和目标 XSD 提供模型构造及实例检查依据；VFB、RTE、Methodology 与建模指南解释组件通信和建模语境。ETAS 工具链下 RH850 工程的 ARXML 提供接口、端口、Runnable、TimingEvent 与变量访问组合的观察依据。作者通过去上下文化、命名规范化、分解和重组形成英文需求，并设置合法参数变体。因此，案例具有规范和工程依据，但属于内部设计题集，不是真实客户需求的独立抽样，也不是官方测试基准。

表 A1 案例设计内容及其来源

| 内容 | 工程观察或规范依据 | 作者设计及评价范围 |
| --- | --- | --- |
| 接口与端口 | 三个 MCU 提供接口、三个 HCU 需求接口及对应数据元素 | 重组接口组合，规范化一个数据元素名称 |
| 周期与超时 | 基线周期 0.01 s；基线接收超时 0.3 s | 周期取 0.005、0.015、0.02 s 等变体；超时取 0.05、0.1、0.2、0.4、0.5 s |
| 接收通信属性 | 超时处理 NONE；规范要求所选结构具有初始值 | 工程样例未提供初始值，实验统一选择数值 0 |
| 最小层，6 案 | 单提供端口或单需求端口 | 隔离接口和接收通信属性构造，不要求内部行为 |
| 标准层，7 案 | 端口、周期执行与访问组合 | 2–3 个端口、一个 Runnable、一个周期事件及 2–3 个访问 |
| 完整层，7 案 | 三个提供端口与三个需求端口的组合 | 1–3 个 Runnable、多个周期及参数变化 |
| 系统外围 | 组件需要在给定上下文中检查 | 不生成系统连接及部署，不评价完整 ECU 或 RTE 合规 |

20 个案例共规定 33 个提供端口、32 个需求端口、18 个 Runnable、18 个周期事件和 55 个变量访问；这些是基础任务中的构造数量，未乘三次重复。

### A.2 生成与验收设置

生成采用请求模型 `gpt-5.6-luna`、low 推理强度、温度 1.0 和严格结构化输出，最大输出预算为 128,000 词元。三个固定种子为 104729、130363 和 155921。每个预定运行执行一次完整流程，生成阶段关闭失败后的自动修复，受控修复另设集合。流程利用任务分析结果及图谱中的元模型、约束和上下文组装生成要求，再经结构化生成、确定性处理和序列化形成 ARXML。除英文描述，案例的结构化规格与既有接口目录也作为输入提供精确对象、引用和数值，由适配器绑定；同一案例规格也为原任务验收提供期望值。因此，本实验未独立评价模型从自然语言提取这些精确要求的能力。

原任务验收器从案例定义读取组件名称、端口集合、引用目标、初始值、超时、Runnable、周期及读写关系，直接与保存的 ARXML 比较，并检查目标 XSD、本地引用和适用领域要求。计划一致性检查另以任务分析计划为期望来源。二者的分开记录使“符合生成计划”与“满足原任务”得以区分；原任务验收仍只覆盖已编码义务，并不是对原始自然语言的全面专家评价。

20 案各重复三次，形成 60 个工件束：最小层 18 个、标准层 21 个、完整层 21 个，全部通过声明范围内的原任务验收。它们共含 255 份 ARXML，其中组件文件 60 份、接口文件 195 份，全部通过 XSD；2,418 项案例结构义务和 675 项本地引用检查均未发现失败。所有输出在全部规范语料范围内仍为未完成，因为部分规则要求的系统上下文、运行轨迹或外部证据不在任务输入中。

这些通过数属于完整流程。49 个运行记录了合计 527 次确定性归一化或恢复事件，涉及身份派生、结构化值绑定及冗余选择处理等。它们是处理事件，不是独立的失败案例。干预前任务分析响应正文未在已核查材料中定位，因此处理后的计划及事件记录不能完整替代原响应。正式生成总用量为 11,967,476 词元，流程耗时均值为 64.712 s；该口径包括整个调用流程。

| 约束关联 | 6,533 | 记录中统计的约束关系 |
| 结构节点／结构关系 | 11,177／14,106 | 多种元模型表示对象及关系，节点数不等于类数 |

发布状态由整理、绑定及实现问题派生，472 条标记为 approved，613 条标记为 needs_review；已整理记录中也有一条绑定未解决。上述状态不代表专家签署。

可重建的形成过程包括从标注规范恢复规则标识与上下文、展开已有整理决定、绑定实体、显式修订及发布。实现中存在 LLM 辅助抽取能力，但现有记录不能逐条证明全部存量均来自一次完整留存的 LLM 抽取。又因缺少独立语义参照和有无元模型上下文的对应对照，本研究不报告该存量的抽取准确率、链接准确率或术语注入的独立增益。RQ1 的证据是来源与模型元素能够被组织并衔接到执行。

### B.2 检查实现及评价独立性

自定义检查由 LLM 辅助人工编写，作者负责规则解释、检查范围、代码采用及测试。运行时装配已有实现：结构化记录提供规则标识、来源、对象选择器、参数与前置条件，规则映射决定调用哪个已注册实现。已有声明操作表达范围、枚举、基数、互斥、存在性及引用要求；其他可判定关系由专用插件处理。未完成规则级确认的候选保持草稿，任务执行期间不自动综合新的验证器。

表 B2 验证职责、依据与适用边界

| 检查职责 | 依据及执行对象 | 与其他检查的关系 |
| --- | --- | --- |
| 序列化与模型符合性 | AUTOSAR XSD；铁路 EMF 对实际 XMI 的加载与模型诊断 | 检查格式及已表达的模型结构，不涵盖所有任务语义 |
| 领域关系 | 已有声明操作、AUTOSAR 插件及铁路 VIATRA 查询 | 只评价已实现且上下文充分的性质 |
| 任务验收 | 案例定义或公开任务义务与实际制品的比较 | 核对名称、数量、引用、周期及指定语义要求 |
| 计划一致性 | 制品与保存的生成计划比较 | 能定位构造偏差，不能替代对原任务的验收 |
| 修改范围及保持性 | 允许字段、保护对象与修改前通过项 | 检查修复是否越界或使已满足的要求退化 |

这些职责可能同时检查同一对象的不同性质，不是互斥的语义类别。代码测试覆盖显式违反、缺失引用范围、缺失任务上下文、未实现规则及插件注册等行为；测试通过支持已测试条件，不能代替规范语义的独立参照。需要运行轨迹、生成代码或外部证据的义务保持未完成，不因其他检查通过而消失。

一个具体例子是周期 Runnable 约束 TPS_SWCT_01519。其来源记录关联 RunnableEntity、SwcInternalBehavior 和 TimingEvent；任务上下文把它绑定到一个具体 Runnable，保存报告显示一个适用对象、一个实际检查对象及通过结果。插件检查事件存在、事件指向该 Runnable 且周期可解析为数值。若原任务要求 10 ms，精确值仍须由读取案例定义的验收器另行核对。该记录的语义状态仍为暂定，展示执行结果没有改变其复核状态。

原任务验收与计划检查具有不同期望来源，但不能据此称所有评价器均与系统完全独立。铁路还用独立编写的关系查询交叉核对原生查询的匹配集合；PIL 则采用人工参考判断，其共同交付评分复用运行时审计函数。各自的独立性只适用于明确说明的部分。

## 附录 C 本地受约束解码实验

### C.1 相同提示下的解码控制

本实验使用 Qwen3.5-9B、vLLM 与 XGrammar，在两张 RTX 4090 上顺序执行请求，张量并行度为 2。温度为 0，top_p 为 1，关闭 thinking、推测解码和前缀缓存，最大输出为 16,384 词元。20 个案例各使用三个固定种子；每个案例与重复组成区组，U、G、A 的六种执行排列各用于十个区组。模型、提示及采样设置在组内相同。

三组提示都包含完整英文需求、输出说明及同一 JSON Schema。U 只通过提示提供约束；G 另将契约交给结构化输出后端执行；A 在 G 的基础上记录逐步审计。比较所回答的是：当提示已给出要求时，执行解码约束能否减少结构违反，以及记录审计的开销是多少。它不评价有无 schema 提示，也不比较不同语法表示。

案例契约由保存的结构定义预先编译，表达实例字段、数组、嵌套和指定取值。编译资格检查包含符合契约的实例、精确值变异和必需属性删除；实际使用的关键词及数值表达适配所用后端。该证据覆盖本实验的契约子集，不等于完整 JSON Schema 标准的支持证明，也不评价完整 AUTOSAR 流程中任务分析及图谱检索的效果。

正式集合含 180 个请求，开发与资格检查不计入评价。所有正式请求都产生完整、可解析的单个 JSON 值，差异出现在是否满足执行契约。

| --- | ---: | ---: | ---: |
| 最小，6 案×3 次 | 9/18 | 18/18 | 18/18 |

### C.2 配对分析与审计代价

案例级比较得到五个改善、零个恶化、十五个持平，双侧精确符号检验 p=0.0625。运行通过率提高 25 个百分点属于描述性结果；三次重复不能作为三个独立任务来增强显著性。题集内部设计及案例数量有限，也限制了对未见需求的推广。

## 附录 D 铁路模型实验

### D.1 任务来源与原生规则

铁路实验复用 Train Benchmark 的元模型和六条 VIATRA 查询 [13]。类型、属性、关联和既有领域查询来自上游；英文需求、服务衔接、维护预备、冗余监测、允许字段及故障注入由作者设计。作者同时提供结构化任务规格，确定性程序据此编译约束和结构计划，LLM 为公开字段选择取值。这一实例评价既有建模语言中的配置和修复，不评价任意自然语言到元模型或任务规格的自动抽取。

24 个基础任务由三个任务族与八种布局组合而成。布局包括链式、分支汇合、环、自环、共享道岔、分离线路、多区域和分支环。任务族调整服务衔接、维护预备和冗余监测要求；例如维护预备要求一条路径停用、另一条启用，冗余监测增加指定传感器的监测关系。任务共享模板祖先，并在开发期间可见，不能当作 24 个独立来源模板。

表 D1 原生查询的约束含义

| 查询 | 本实验执行的性质 |
| --- | --- |
| PosLength | 区段长度为正 |
| SwitchMonitored | 每个道岔应被传感器监测 |
| SwitchSet | 对启用且入口信号为 GO 的路径，计划道岔设置与实际位置一致 |
| RouteSensor | 路径包含对其计划道岔实施监测的传感器要求 |
| ConnectedSegments | 同一传感器不监测形成六区段有向游走的所有区段；顶点不要求互异 |
| SemaphoreNeighbor | 不同路径要求的传感器所监测的相邻轨道满足原查询规定的公共边界信号机关联 |

规则释义用于解释实验，实际匹配以保留的原生查询为准。尤其不能把 ConnectedSegments 改写为要求六个不同顶点的简单路径。原生规则之外，任务验收检查指定服务状态与关系，修改保护检查核对不可改字段；这些性质不能由原生查询全部替代。

### D.2 生成、验证与修复条件

主实验采用 `gpt-5.6-luna`、low 推理强度、温度 1.0、128,000 词元最大输出预算和三个固定种子。生成请求包含需求、任务义务、结构计划、可赋值字段及六条规则。响应是完整字段赋值，经字段域和引用范围检查后装配为 XMI；对象身份、集合与固定物理连接由程序保持，约定的反向关联由确定性程序闭合。

验证直接读取实际提交的 XMI，检查加载、根对象、身份、模型诊断、引用、六条原生查询、公开任务义务及保护字段，不先重写制品再以替代文件证明原文件有效。独立编写的关系查询用于交叉核对原生匹配集合。严格成功要求适用检查全部完成并通过，赋值拒绝和未生成制品也保留在预定分母中。

## 附录 E 结构化法律决策实验

### E.1 案例、证据与比较条件

PIL 补充实验考察检索、生成时结构约束、生成后审计与一次修复对浅层 JSON 决策的影响。输入是英文事实情景，输出包含结论、管辖类型、依据和理由。它直接从事实及证据生成决策，没有独立因素抽取、元模型转换或完整 ICM 构建，因此不作为工程模型符合性或完整方法跨领域迁移的证据。

60 个合成情景由 Xinyue Yang 依据相关规范设计，涵盖管辖依据、程序关系、国内法转介和机关权限等情形，并按共同设计来源组织为 31 个依赖簇。Xinyue Yang 与 Yirui Wang 初轮分别作出参考判断，未查看对方初轮结果，随后共同讨论分歧；Codex 辅助整理和填写。参考判断在正式生成前确定。初轮独立性不意味着两位评审均独立于案例设计，也不构成对全部模型输出的逐条实体审评。

检索材料依据 Brussels I bis 的 2015 年 2 月 26 日合并文本 [14]，以及欧盟商标条例的 2025 年 12 月 1 日合并文本 [15]。58 条英文证据为条款转述，使用法律文书与条款的联合标识，案例及证据另经输入等价复核。支持库依据同一批案例的可接受证据组织，检索器也在该题集上开发并检查覆盖，故不属于未见案件的法律检索测试。运行时没有向模型提供 gold 或可接受答案集合。

正式集合由 60 案、四组、三次重复构成，共 720 个预定单元，每组 180 个。正式设计在先导检查后固定，使各组提示获得相同的输出契约信息；先导结果整体排除，不与正式结果混合。该设计不被描述为完全未受先导研究影响的首次预注册。

### E.2 审计器、参考判断与终点

运行时审计器由 LLM 辅助人工编写，接受决策、输出结构、交付规则和允许引用的证据集合，不读取案例 gold。它检查字段类型与枚举、弃权和条件标记之间的约定、主要与备选类型关系、部分结论和条款对应、引用是否来自检索证据，以及自然语言字段中的中文字符。后者只是字符检测。已编码关系不等于完整法律推理，引用范围正确也不保证理由充分；案例评审不被扩展为对审计器全部代码和规则的专家认证。

P3 把原事实、相同证据、原答案和审计诊断交给模型，在相同 schema 下提出一次修订，再由同一审计器复验；没有逐案人工编辑或运行时读取参考答案的分支。仍失败者保留规范化关闭记录，不发布答案。离线评分对所有组执行共同交付检查，且复用运行时审计函数，因此人工参考判断具有单独来源，而交付评分与系统检查并非实现上独立。

主要复合终点要求结构有效、共同交付规则通过、四项参考义务兼容且实际发布，四者同时满足。参考义务要求结论和主要管辖类型分别属于可接受集合，引用与非空必需证据集合至少有一项交集，条件标记与参考值一致；必需证据为空时无该交集要求，备选类型不能补救错误的主要类型。该定义不完整判断自由文本法院、国家、理由或缺失事实内容，因此称参考判断兼容，不称完整法律正确率。

按已确认意见，case42 中消费者另行确认条款仍需考虑 Articles 19 和 25(4)，不能据此认定所有保护性要求已经满足。条件标记的后续说明明确评价所选 conclusion 本身，而允许理由讨论后续结果未知；这不放宽为任意布尔值均可接受。该说明未倒填入本批提示，结果不衡量使用澄清提示后的表现。三条意见之外的 717 个单元没有本次新增实体意见；其对应案例的历史参考判断评审仍然保留，完整法律正确率不予估计。

## 附录 F 材料与可复核范围

随文复现包提供案例及来源、配置、核心实现、保留输出、评价程序和结果关联。安装依赖后可离线检查文件身份并重算制品判定，无需再次调用模型。复核覆盖 AUTOSAR 任务验收与受控修复、本地解码结构结果、铁路原始 XMI 的原生检查，以及 PIL 原评分、输入修正和定向意见。配置、源码、依赖与操作命令见包内说明。

留存范围限制了重放能力：AUTOSAR 的干预前任务分析正文和完整修复交互未在已检查材料中定位；本地解码缺少完整历史 logits、掩码和部分历史环境身份；铁路部分请求用量未知。提供方返回的模型名和固定 seed 也不等于独立认证上游身份或保证确定性重放。离线一致性说明保存制品与报告可核对，不证明缺失交互已恢复，更不把预期失败模型改称全部通过。材料通过实际提交的文件或获授权的仓库访问提供，私有地址不被描述为公开归档。
