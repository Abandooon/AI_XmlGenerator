# PIL V4.1 统一四臂复制实验协议

版本：2026-09-04 付费运行前冻结候选  
当前状态：`READY_FOR_PAID_AUTHORIZATION`；英文翻译/法源等价复核、零网络代码审计与预检均已通过，正式执行仍关闭，V4.1 模型/API 调用为 0

## 1. 研究定位与可陈述范围

PIL V4.1 是 ATLAS **分层约束与验证子契约**在国际私法结构化裁判任务上的前瞻冻结复制实验。它不是完整 ATLAS 产物生成流水线的跨域复刻：PIL 输出是浅层 JSON 裁判记录，不包含 AUTOSAR 实验中的确定性 XML 骨架、跨文件引用材料化或同等的深层工件构造。它受到既有 V2 先导结果及其事后测量审计的启发，因此不能包装成未受既有数据影响的首次预注册。它要回答的是：在同一案例集、同一模型、同一语义输出契约和同一评分器下，接地检索、L1 结构约束以及 L2 审计/一次修复分别带来多大增量。

旧 V2 的 60 案例 × 3 臂 × 3 次、共 540 个结果单元及其解析审计保持原样。V4.1 不覆盖、不改写、不合并 V2。五个案例的事实经双人复核后改变，因此 V2 对这些旧事实的输出不得拿来对 V4.1 gold 计分。另有一个 V4 设计审计批次在 132/720 单元后因 P1/P2 输出契约信息不等而停止；其 136 次逻辑模型调用全部归档并排除，不得续跑、择取或进入论文结果表。

本实验的统计外推范围仅是这 60 个经双评审复核的合成法律情景。案例不是司法案件的概率样本，领域也不是从领域总体抽样；V4 无法证明对未见领域的普遍泛化。案例设计者是一名研究方向为国际私法的研究生；论文应如实披露其身份和双评审流程，不把该数据集称为官方、真实案件抽样或专家基准。

## 2. 案例与 Gold 的证据链

案例最初由一名研究方向为国际私法的研究生依据 Brussels I bis 等规范设计，不是真实案件记录。V4.1 gold 的来源链固定为：

- 51 案：第一评审与独立第二评审兼容一致；
- 4 案：两名原评审完成联合分歧共识；
- 5 案：事实或标签修订后，两名原评审再次联合确认；
- 合计 60/60，且所有共识均在 V4 模型输出产生前锁定。

随后由现有国际私法研究生评审完成 60 条英文案例与 58 条英文证据的逐行中英语义/法源等价复核：54 条案例和 55 条证据直接通过，6 条案例与 3 条证据按意见修订后通过，未决项为 0。该步骤只确认输入等价性，不重新裁决 gold。

推理文件只含 `id`、`cluster_id`、`facts_text`、`source_class`；gold、连接点和可接受答案集合位于独立文件。主标签新增并区分：

- `Authority_of_X_has_jurisdiction`：行政机关权限，不伪装成法院管辖；
- `related_actions` / `May_stay_or_decline_for_related_actions`：Article 30 的相关诉讼，不并入 Article 29 的同诉因先受理。

法条证据使用 `instrument:provision` 唯一身份，例如 `BRUSSELS_I_BIS:Art.63(1)` 与 `EU_TRADE_MARK_REGULATION:Art.63(1)` 不再混同。

## 3. 四臂与可识别比较

| 臂 | 证据 | 解码期结构 | 运行时后验处理 |
|---|---|---|---|
| P0 | 无 | 提示要求统一 JSON | 无审计、无修复 |
| P1 | 固定 top-12 词汇检索 | 提示要求同一 JSON | 无审计、无修复 |
| P2 | 与 P1 相同 | 严格 JSON Schema（L1） | 无 L2 审计、无修复 |
| P3 | 与 P1/P2 相同 | 严格 JSON Schema（L1） | 确定性 L2 审计；失败时最多一次严格修复，仍失败则关闭 |

四臂共用模型、推理强度、最大输出长度、案例、重复次数、英文系统消息、英文案例事实、英文法条摘要、完整 JSON Schema 和事后评分器。P1/P2/P3 的主提示词及证据逐字节相同；P2 相对 P1 的 provider payload 只增加严格 `response_format`。P0/P1 仅接受标准 `json.loads`；Markdown 围栏、解释性前后缀或启发式关键词修补均不接受。由此消除 V2 中“自由文本关键词投影对比严格 JSON”的测量不对称。

冻结 provider 契约经 AUTOSAR V20 最终证据包独立核验后对齐：请求模型 `gpt-5.6-luna`，且仅接受返回快照 `gpt-5.6-luna-2026-07-09`；非流式 Chat Completions、`low` 推理强度、`temperature=1.0`、128000 最大 completion token、180 秒请求超时、无工具、SDK 隐式重试 0。三次重复分别固定为 provider best-effort seed `104729`、`130363`、`155921`。对可识别的瞬时传输错误，一个逻辑请求最多按 V20 的 8-attempt 延迟表继续；这些是同一实验单元内的传输证据，不是额外观测。正式授权还会绑定规范化 API base 的 SHA-256，执行器在第一次请求前核验模型协议、运行时包版本和端点身份。

固定比较为：

- `P1 − P0`：冻结检索/接地的增量；
- `P2 − P1`：L1 严格结构解码的增量；
- `P3 − P2`：L2 审计与一次有界修复的组合增量；
- `P3 − P0`：完整流水线相对统一自然基线的总体效果。

`P3 − P2` 不能进一步分离审计和修复。检索器在运行前使用 gold 必需证据做了 60/60 覆盖资格检查，因此 `P1 − P0` 是“已通过资格检查的固定检索器”的条件效应，不代表任意 RAG 系统。

## 4. 统一输出与评价契约

所有臂都必须给出：`conclusion`、`forum`、原子 `forum_type`、`alternative_forum_types`、`conditional_answer`、`explicit_abstention`、带 instrument 的 `legal_basis`、`reasoning`、`missing_facts`。

主要终点 `endpoint_success` 同时要求：

1. 可解析且符合统一 Schema；
2. 通过冻结的共同交付规则；
3. 结论、主要/可接受管辖类型和至少一项 gold 必需证据兼容；
4. 系统实际放行该结果。

同时报告结构有效率、共同交付有效率、语义正确率、错误放行率、证据 precision/recall/F1、覆盖率、P3 修复触发/恢复/引入错误、逐响应 input/output/total token、逻辑模型请求数和包含重试在内的传输请求数。P3 的审计器不是法律正确性 oracle；法律正确性由运行前冻结的双人共识 gold 独立判定。

## 5. 样本量、依赖与统计

- 60 案例 × 4 臂 × 3 次独立重复 = 720 个预定单元；
- 推断单位为案例，先在案例内汇总三次重复；
- 固定 20,000 次案例级配对 bootstrap 与配对符号检验；
- 60 案映射到 31 个冻结依赖簇，另报依赖簇 bootstrap 敏感性分析；
- ITT 为主要口径，条件于系统放行的质量是次要口径；
- 不把 V2 与 V4、不同模型或不同领域的结果合并。

## 6. 失败关闭、付费边界与不可变性

- 模型拒答、截断、空输出、无效 JSON 或规则失败均保留为模型结果；
- 未得到可用模型结果的基础设施故障写入独立哈希链尝试日志并立即终止；再次启动默认拒绝重试该单元，只有显式给出精确 `--retry-failed-unit UNIT_ID` 才能再次付费；
- SDK 隐式重试为 0；瞬时传输继续策略与 AUTOSAR V20 一致，最多 8 次且保留 attempt evidence；P3 语义修复调用最多一次；
- 720 个单元按固定哈希交错；每个完成单元即时写入追加式哈希链，禁止重跑或择优保留；
- 数据、gold、知识库、Schema、规则及关键运行实现均记录 SHA-256；任一文件漂移即阻断；
- V4 专用 provider 实现、模型/推理协议、Python 与关键包版本均进入预检并在第一次请求前复核；
- `PIL_V41_PREFLIGHT_READINESS.json` 永远保持 `formal_run_enabled=false`；
- 完整的 240 份不同主提示词保存在 `PIL_V41_RENDERED_PROMPTS.jsonl`；三次重复由正式 schedule 绑定相同提示词哈希和不同固定 seed；
- 零网络代码审计 `PIL_V41_PREPAID_CODE_AUDIT.json` 必须 PASS，且其实现哈希必须与预检一致；
- 英文案例与 58 条英文证据已全部通过人工等价复核，完成表及其 SHA-256 已写入验收、代码审计和预检；下一步只能显式运行 `pil_v4_authorize.py --confirm-paid-run PIL_V41_720_LOCKED` 新建 `PIL_V41_FORMAL_READINESS.json`；
- 正式 schedule 只能引用该独立授权文件，前端没有授权或 provider-client 能力。

## 7. 论文决策规则

V4 完成前，PIL 只能支持分层约束与验证子契约已被构造性实例化、双人 gold 流程已完成以及测量风险已被修复。完成后，效果主张必须跟随预定比较的实际点估计和区间：无优势、区间跨零或方向相反都必须如实保留。即使 P3 优于 P0，也只能称为本 PIL 案例集上这一**简化子契约**的可迁移有效性证据；不能据此声称完整 ATLAS 产物流水线在法律域有效、跨域机制不变性或对领域总体的统计泛化。
